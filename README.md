# うたログ / Karaoke Performance Log

既存のSites版うたログをReactの画面・記録構造ごと移植した個人用アプリ。Cloudflare専用アドレスでログインを保持し、旧GitHub Pagesも継続利用できます。

- IndexedDB（専用DB名）に歌唱記録・タグ・採点機を保存。永続化を申請。
- 全件・検索結果のMarkdown／コピー、全件JSONバックアップ、確認付き復元。
- 復元はファイルの内容に置き換え。復元前のデータをダウンロードし、端末にも直前1世代を保持。
- 150件から50件ごとの通知。全件の閲覧用出力とJSON出力の両方で解除。
- 採点機は新規保存時の選択を引き継ぐ。歌唱姿勢は任意、次の記録・過去曲呼び出しには引き継がない。
- 公開コードに個人データ・秘密キーを含めない。クラウドへはユーザーの送信・復元操作でだけスナップショットを追加。
- ホーム画面追加、オフライン起動、noindex対応。noindexはアクセス制限ではない。

## 開発

Node.js 22以上。`npm ci` → `npm test` → `npm run build`。
`npm run build`は`dist`とリポジトリ直下に同一の公開ファイルを生成する。生成物もコミットする。Pagesはmainブランチのrootから公開。GitHub Actionsでテストとビルドの一致を確認する。

## 移行

移行用JSONを「設定・データ管理」から選択し、件数を確認して復元。
クラウドのスナップショットに含まれないスマホ内の最新記録は別途照合が必要。
復元後に表示する件数・全項目照合結果を確認し、元のSitesはそのまま保持する。
JSONファイルはこの公開リポジトリにアップロードしない。

## バックアップ通知

記録数の最高到達件数を保持し、削除と再追加で同じ節目を繰り返さない。
検索結果のみの出力は全件が含まれる場合に限って通知解除に数える。
ダウンロード開始後のファイル保存・キャンセルはブラウザから検知できないため、利用者はダウンロード先を確認する。

## 更新

アプリを更新する際は`public/sw.js`のキャッシュバージョンも変更する。
起動中の全タブを閉じて再度開くと待機中の更新が有効になる。

## ログイン保持とCloudflareへの移行

専用アプリ: https://karaoke-performance-log-backups.dengana-10011212.workers.dev/

旧アドレスの「移行用の全データJSONを保存」でファイルを保存し、専用アドレスで端末名・復旧キーを入力して初回ログインします。「全データJSONの復元内容を確認」でファイルを選び、日時・件数を確認して復元してください。移行は本人の端末から行います。旧アドレスのIndexedDBを削除・更新しません。

クラウド専用の端末Cookieにはサーバー側の自動失効期限を設けません。端末ごと、または全端末のログイン解除が可能で、端末一覧・解除には復旧キーでの本人確認が必要です。ブラウザのCookie消去、プライベートモード、ブラウザ自身の保持制限では再ログインが必要になります。詳しい配備・認証仕様は `cloudflare/README.md` を参照してください。

## クラウドの保持数と送信ボタン

全端末で共有するクラウド履歴は、最新1件＋過去4件の計5世代を保持します。新しい送信をDBから読み戻して完全照合できた後に、6世代目以降のメタデータとJSONチャンクを原子的に削除します。更新・任意削除APIは設けません。通信中断で成功が未確認なら同じ送信を再試行できます。整理・照合に失敗した保留データは旧5世代を押し出さず、確認成功まで保護します。復元前の退避バックアップも1世代に数えます。

この端末の前回送信日時の日本時間の日付が今日なら、送信ボタンは画面下部のクラウド設定の直前（設定・データ管理のすぐ上）に表示し、固定しません。未送信または日付が変わったら上段に表示して送信を促します。日本時間0時、再表示、フォーカス復帰で再判定し、位置を変えてもログイン状態や入力・履歴を維持します。
